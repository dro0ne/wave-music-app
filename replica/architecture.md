# Архитектура: «Волна» (функции Dotify на легальных источниках)

Основа: `replica/recon.md` и `replica/features.csv`. Дата: 2026-10-26.

Главное ограничение: **сервера пока нет.** Сайт живёт на GitHub Pages (только статические
файлы), поэтому всё новое работает прямо в браузере. Код на Python в `server/` (аккаунты,
импорт, кэш каталога) остаётся и включится, когда сервер появится. Сейчас эти функции на
GitHub Pages не работают.

## Стек

Новый стек не берём: «Волна» уже написана на чистом JS без сборки, и переписывать её на
Next.js ради клона нет смысла.

| слой | выбор | почему |
| --- | --- | --- |
| веб | как сейчас: vanilla JS, без сборки, по скрипту на модуль | уже работает, тесты есть, деплой одной командой `git push` |
| стили | `styles.css` + токены из `/replica-design` в `:root` | так уже устроено |
| хранение в браузере | `localStorage` для настроек (как сейчас, `waveState`) + **IndexedDB** для библиотеки, кэшей и файлов | плейлисты, тысячи сопоставлений и тексты не влезают в localStorage; IndexedDB хранит и дескрипторы локальных файлов |
| база на сервере (потом) | SQLite, как у `server/accounts.py` | один файл, без отдельного сервиса; для одного пользователя с запасом |
| вход в «Волну» | `server/accounts.py` (потом) | уже написан |
| вход в Spotify | OAuth Authorization Code + PKCE прямо из браузера | сервер и секрет не нужны |
| воспроизведение | три «движка»: `<audio>` (файлы, Audius), Spotify Web Playback SDK, YouTube IFrame API | официальные способы, других нет |
| тексты | LRCLIB (`lrclib.net/api`) | открытый, без ключа, отдаёт синхронные LRC, разрешает запросы из браузера |
| звук | Web Audio API: `BiquadFilterNode` ×10, `ConvolverNode`, `StereoPannerNode` | встроено в браузер; цепочка звука уже есть (анализатор для фона) |
| платежи, почта, фоновые задачи | нет | личное использование, подписки не делаем |
| хостинг | GitHub Pages, `main` | так сейчас; сервер потом через `server/deploy.sh` |
| десктоп | сначала **PWA** (установка из Opera GX или Chrome), Tauri потом | в Tauri на Windows (WebView2) нет Widevine, без которого не работает плеер Spotify; PWA в Opera GX его поддерживает |
| Android | сначала **PWA** + Spotify Connect, Capacitor потом | плеер Spotify официально не работает в мобильных браузерах; на телефоне «Волна» управляет официальным приложением Spotify |

## Источники и движки

Для каждого трека `resolveTrack` в `sources/source-manager.js` уже перебирает варианты по
приоритету. Добавляем два новых источника и понятие **движка**: как трек проигрывается.

| приоритет | источник | движок | эквалайзер и эффекты | анализатор для фона | скорость |
| --- | --- | --- | --- | --- | --- |
| 1 | `local`, свои файлы | `<audio>` | да | да | да |
| 2 | `audius` (и остальные открытые) | `<audio>` | да, если `waveAnalysisAllowed` | да | да |
| 3 | `spotify` | Web Playback SDK / Spotify Connect | нет | нет: фон двигается по BPM | нет |
| 4 | `youtube` | IFrame | нет | нет: фон по BPM | да (`setPlaybackRate`) |

Интерфейс движка (новый файл `playback-engines.js`):
`load(track)`, `play()`, `pause()`, `seek(sec)`, `setVolume(0..1)`, `setRate(x)`,
`position()`, `duration()`, события `ended`, `error`, `state`, флаг `supportsEffects`.
Кроссфейд работает только между двумя треками на `<audio>`. При переходе на Spotify или YouTube
и обратно звук просто сменяется.

## Схема

Сейчас всё лежит в IndexedDB (база `wave`, 8 хранилищ). Когда появится сервер, те же таблицы
в SQLite (`replica/schema.sql`) синхронизируются по `updated_at`. Id создаются на клиенте
(`crypto.randomUUID()`), поэтому записи, сделанные без сети, потом сольются без конфликтов
id. Время хранится в миллисекундах UTC (в SQLite нет `timestamptz`).

Доступ: **проверка в слое данных.** У SQLite нет row level security, поэтому каждый запрос
на сервере фильтрует по `user_id`, который берётся из токена сессии, и никогда из тела запроса.
В браузере все данные принадлежат одному пользователю.

| хранилище / таблица | что | ключ | индексы |
| --- | --- | --- | --- |
| `tracks` | метаданные трека (название, артисты, альбом, длительность, обложка, ISRC если есть) | `id` | `dedupe_key` |
| `track_sources` | где трек нашёлся: `spotify:<id>`, `youtube:<id>`, `audius:<id>`, `local:<id>`, с оценкой совпадения | `track_id + source` | `source + source_id` |
| `playlists` | плейлисты пользователя и импортированные | `id` | `user_id + pinned + position` |
| `playlist_tracks` | треки в плейлисте с позицией и датой добавления | `id` | `playlist_id + position`, `track_id` |
| `lyrics` | кэш текстов из LRCLIB и ручной сдвиг пользователя | `track_id` | — |
| `eq_presets` | свои пресеты эквалайзера | `id` | `user_id` |
| `import_jobs` | импорт по ссылке: прогресс, найдено N из M, можно продолжить | `id` | `user_id + created_at` |
| `local_files` (только в браузере) | дескрипторы файлов и папок, теги | `id` | `track_id` |

Лайки, дизлайки, история, настройки звука и оформления остаются в `waveState`. Они уже
синхронизируются через аккаунт и небольшие.

Жёсткие ограничения: трек не может быть дважды в одном плейлисте (`unique(playlist_id, track_id)`),
позиции в плейлисте уникальны, `track_sources.confidence` от 0 до 1.

## API

Своих маршрутов пока нет: сервера нет. Все вызовы идут из браузера в официальные API с ключами
пользователя.

### Spotify (Web API + Web Playback SDK)

| метод и путь | что делает | кто | вход | выход | сценарий |
| --- | --- | --- | --- | --- | --- |
| `GET accounts.spotify.com/authorize` → `POST /api/token` | вход по PKCE, обновление токена | пользователь | client_id, code_verifier | access (1 ч) + refresh token | F02 |
| `GET /v1/me` | проверить Premium и страну | пользователь | — | `product`, `country` | F02 |
| `GET /v1/search?type=track&q=track:… artist:…` | найти трек для сопоставления | пользователь | название, артист | кандидаты с длительностью и ISRC | F01, F05 |
| `PUT /v1/me/player/play?device_id=…` | включить трек в плеере SDK или в приложении (Connect) | пользователь, Premium | `uris` | 204 | F01, F02 |
| `GET /v1/me/player/devices` | найти устройство (телефон, ПК) | пользователь | — | список | F02 на Android |
| `GET /v1/me/tracks`, `GET /v1/me/playlists`, `GET /v1/playlists/{id}/tracks` | импорт своей библиотеки Spotify | пользователь | — | треки | F05 |
| `PUT /v1/me/tracks` | лайк в «Волне» → лайк в Spotify (по желанию) | пользователь | ids | 200 | F02 |

Scopes: `streaming user-read-email user-read-private user-read-playback-state
user-modify-playback-state user-library-read user-library-modify playlist-read-private
playlist-read-collaborative`.
Redirect URI: `https://dro0ne.github.io/wave-music-app/` и для разработки
`http://127.0.0.1:8765/` (`localhost` Spotify больше не принимает).

### YouTube

| метод и путь | что делает | кто | вход | выход | сценарий |
| --- | --- | --- | --- | --- | --- |
| `GET youtube/v3/search?part=snippet&type=video&videoCategoryId=10&q=…` | найти трек, которого нет в Spotify | ключ API, ограниченный доменом | артист + название | id видео | F01, F05 |
| `GET youtube/v3/videos?part=contentDetails&id=…` | длительность для проверки совпадения | то же | ids | duration | F05 |
| IFrame Player API | воспроизведение | — | videoId | события | F02 |

Квота: 10 000 единиц в день, поиск стоит 100 → около 100 поисков в день. Поэтому YouTube
ищется только когда трека нет у первых трёх источников, а результат навсегда сохраняется в
`track_sources`.

### Остальное

| метод и путь | что делает | сценарий |
| --- | --- | --- |
| `GET lrclib.net/api/get?track_name&artist_name&album_name&duration` | синхронный текст | F03 |
| `GET lrclib.net/api/search?q=…` | запасной поиск текста | F03 |
| Audius, Internet Archive | как сейчас | F01 |
| `POST /api/import` (сервер, потом) | импорт ссылок Яндекса, Deezer и Apple | F05 |

Входящие вебхуки: нет. Исходящие: нет.
Задачи по расписанию: нет. Импорт и сопоставление идут в браузере, пока открыта вкладка, и
продолжаются с того же места при следующем открытии.

## Что может укусить

- **Widevine.** Без него плеер Spotify не запускается. Он есть в Opera GX, Chrome, Edge и
  Firefox, но его нет в WebView2 (Tauri) и в Android WebView. Отсюда решение: PWA, а на
  телефоне Spotify Connect. Проверить первым делом.
- **Ограничения Spotify для новых приложений.** С ноября 2024 новым приложениям недоступны
  audio-features (BPM), recommendations, related artists и треки редакционных плейлистов
  Spotify. Поиск, воспроизведение и своя библиотека доступны. Приложение в режиме разработки
  работает для владельца и нескольких добавленных вручную пользователей. Для личного
  использования этого хватает.
- **Spotify разрешает только один активный плеер на аккаунт.** Если Spotify играет на
  телефоне, «Волна» на ПК его перехватит, и наоборот. Это нужно честно показывать в интерфейсе.
- **Правила YouTube.** Видео нельзя прятать: плеер должен быть видимым, не меньше 200×200, и
  нельзя проигрывать только звук. Поэтому для YouTube-трека на месте обложки показывается
  видео. В фоне на телефоне YouTube играет плохо.
- **Ошибки сопоставления.** Ремиксы, live-версии, кавер-версии, «feat.». Нужна проверка по
  длительности (±4 с, как в `isSameRecording`), а если у Spotify есть ISRC, то по ISRC. Если
  ни один кандидат не набрал уверенности, трек помечается «не найден», а не включается
  первый попавшийся.
- **Лимиты.** Spotify на частые запросы отвечает 429 с `Retry-After`. Импорт 3173 лайков
  идёт очередью, около 3 запросов в секунду, это примерно 20 минут. Прогресс сохраняется,
  импорт можно продолжить.
- **Токены в браузере.** Refresh token Spotify хранится в localStorage. Для личного сайта это
  допустимо. Защита: никакого чужого JS на странице, Content-Security-Policy в `index.html`.
- **CORS и эффекты.** Эквалайзер подключается только к трекам с `waveAnalysisAllowed`. Для
  остальных кнопка видна, но выключена, с подсказкой «недоступно для этого источника».
- **Локальные файлы.** `showDirectoryPicker` есть только в Chromium на ПК. На Android выбор
  файлов через `<input type=file multiple>`. После перезапуска браузер снова спросит
  разрешение на папку.
- **Офлайн.** Кэшировать можно только свои файлы и Audius-треки, где автор разрешил загрузку.
  Spotify и YouTube офлайн не работают.
- **Фоновое воспроизведение на телефоне.** У PWA с `<audio>` оно работает через Media Session.
  Spotify на телефоне играет в собственном приложении, и с фоном там проблем нет.

## Порядок работ

0. **Резервная копия** перед каждым этапом: ветка `backup/<дата>` + `git bundle` в
   `C:\Users\Grok\wave-backups\`.
1. **Проверка стека (вертикальный срез).** Войти в Spotify через PKCE на GitHub Pages,
   найти трек, проиграть его плеером SDK в Opera GX. Для трека, которого нет в Spotify,
   проиграть найденное видео YouTube. Экраны S03, S05; хранилище `track_sources`; вызовы
   `/authorize`, `/v1/me`, `/v1/search`, `/v1/me/player/play`, YouTube search.
   Нужно от пользователя: Client ID Spotify, ключ YouTube API.
2. **Движки воспроизведения.** Вынести `<audio>` в интерфейс движка, добавить движки Spotify
   и YouTube. Существующие тесты (`tests/player-*.test.html`) должны остаться зелёными.
3. **Обязательные функции, по областям:**
   - плеер: очередь S10, перемешивание и повтор, Media Session для всех движков;
   - библиотека: S11, S12, хранилища `playlists`, `playlist_tracks`;
   - импорт: S14, лайки Яндекса и Spotify → плейлист с сопоставлением, отчёт «N из M»;
   - тексты: S06, LRCLIB, хранилище `lyrics`;
   - звук: S07, S08, эквалайзер с пресетами, скорость, всё запоминается;
   - оформление: светлая и тёмная тема (S15);
   - свои файлы: `local_files`;
   - платформы: установка PWA на ПК и Android, Spotify Connect на телефоне.
4. **Желательные:** слова в тексте, сдвиг и стиль текста, реверб, нормализация, таймер сна
   S09, подсказки и история поиска, цвет от обложки, раскладки плеера, кэш для офлайна,
   восстановление очереди при запуске, проверка виджета Яндекса.
5. **Дополнительные:** 8D, бегущая строка, горизонтальный плеер, Tauri и Capacitor (только
   если PWA не хватит), Discord Rich Presence (нужен Tauri), окно мини-плеера.
6. **Исправления от `/replica-entrepreneur`**, когда он отработает.
